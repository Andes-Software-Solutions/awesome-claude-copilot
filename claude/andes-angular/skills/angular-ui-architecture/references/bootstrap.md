# Bootstrap 5.3 + ng-bootstrap

The design-system-agnostic rules of the skill, instantiated for a workspace that compiles Bootstrap 5.3 from `src/styles.scss` and uses ng-bootstrap for widgets, with a light and a dark theme on `data-bs-theme`.

- **Bootstrap first.** The grid, `d-flex` and `gap-*` for layout; spacing and typography utilities; `card`, `list-group`, `alert`, `badge`, `placeholder`, `spinner-border`, `table`. Interactive widgets are standalone ng-bootstrap directives and services (`NgbOffcanvas`, `NgbModal`, `NgbDropdown`, `NgbTooltip`) imported per component — never Bootstrap's JavaScript bundle, never `NgbModule`. Install ng-bootstrap with npm rather than `ng add`: its schematic registers `NgbModule` at the root and writes a Bootstrap SCSS `@import` that current Sass flags as deprecated. `@angular/localize` is the one polyfill ng-bootstrap needs.
- **Compile Bootstrap from Sass** with `@use 'bootstrap/scss/bootstrap' with (...)` in `src/styles.scss`, passing the palette (`$primary`, `$secondary`, `$info`, `$success`, the body and emphasis colours per theme) so components, focus rings, and button text all derive from it. Build Sass with `quietDeps` so Bootstrap's internal deprecations stay silent. Bootstrap Icons may stay precompiled CSS in `angular.json`. Bootstrap and Icons CSS are roughly 315 kB raw; size the `initial` budget with that in mind.
- **Custom CSS reads Bootstrap's variables** — `var(--bs-border-color)`, `var(--bs-primary)`, `var(--bs-body-font-family)` — never hex values. Global partials `src/styles/_<topic>.scss` are pulled in with `@use`.
- **Breakpoints.** Mobile-first at 360 px, then `d-none d-lg-flex`, `col-12 col-lg-9` and friends. A sidebar on large screens becomes an `NgbOffcanvas` on small ones.
- **Two themes on `data-bs-theme`.** Bootstrap bakes `$primary` into components once for both themes, so a primary colour that fails contrast on the dark body gets a `[data-bs-theme='dark']` block in `styles.scss` overriding primary buttons, focus rings, checked inputs, nav pills, dropdown and list-group active items, pagination, and progress. A component that bakes in primary and is missing from that block stays the light-theme colour in dark mode — add it when the app first uses it. Check every text and background pair for WCAG AA under both `data-bs-theme="light"` and `"dark"`; use `text-*-emphasis` where a brand colour is too light as text. A theme store applies the attribute on `<html>` and persists only an explicit choice, so a visitor who never toggles follows the OS.
- **Third-party kits** (a Tailwind-based chat kit, say) are restyled in one global partial that maps their CSS custom properties onto `--bs-*` variables, follows `data-bs-theme`, and adds whatever hook the library keys on, such as a `.dark` class. Its utility classes never appear in our templates; our markup rendered inside it carries an isolating wrapper class the same partial defines, so the library's resets and typography stay out. CSS the kit needs on one lazy page ships as a non-injected style bundle that the page's resolver loads by name.
- **Icons** are Bootstrap Icons — `<i class="bi bi-…" aria-hidden="true"></i>` — beside visible or `visually-hidden` text.
