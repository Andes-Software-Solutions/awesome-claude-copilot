# Layer enforcement

## The ban table

| Files | May not import |
| --- | --- |
| `shared/models/**` | `@angular/*`, `@ngrx/*`, anything else under `src/app` |
| `shared/utils/**` | same, except `shared/utils` |
| `core/**` | `shared/components`, `shared/directives`, `shared/pipes`, `services`, `state`, `components`, `pages` |
| `services/**` | `shared/components`, `shared/directives`, `shared/pipes`, `state`, `components`, `pages` |
| `state/**` | `shared/components`, `shared/directives`, `shared/pipes`, `components`, `pages` |
| `shared/{components,directives,pipes}/**` | `state/<feature>/*`, `components`, `pages` |
| `components/<f>/**` | `pages`, `components/<other>` |
| `pages/<f>/**` | `pages/<other>` |

## ESLint wiring

- Copy `assets/eslint-layer-bans.js` beside `eslint.config.js` and spread its blocks after the angular-eslint and NgRx blocks: `module.exports = defineConfig([...yourBlocks, ...layerBans(__dirname)])`. Options: `srcDir` (default `src`), `banForms` (default `false`; set `true` once the app is on Signal Forms, so `FormsModule` / `ReactiveFormsModule` imports fail), `skill` (the name quoted in messages). In an ESM config, change the `require` / `module.exports` lines.
- One `no-restricted-imports` block per folder, spec files exempt (`ignores: ['**/*.spec.ts']`), each banned folder as its alias (`@state/*`) and as `**/app/state/*`. Per-feature blocks are generated by reading `src/app/components` and `src/app/pages` and negating the feature's own path — the top level only, so a feature's own sub-areas share one block and are not isolated from each other.
- Three traps. Flat config replaces a rule's options when blocks overlap, so every layer block repeats the forms ban instead of relying on a global one. An exception negates the directory itself (`!@components/<f>`, `!**/app/components/<f>`), because the matcher cannot re-include a child of an excluded directory. `no-restricted-imports` matches the import *string*, not the resolved path, so a relative import with no `app/` segment (`../../state/x`) is not caught — cross-layer imports must use the alias; `import/no-relative-parent-imports` closes that gap and `import/no-cycle` keeps the `state/` domain graph acyclic, if the project adds `eslint-plugin-import`.
- NgRx's `signalsTypeChecked` rules are added by hand and scoped to `**/*.ts` (`ngrx-signal-store`); unscoped, its parser would replace the template parser on `.html`.

## Path aliases

One alias per top-level folder, in `tsconfig.json`; no `baseUrl` (deprecated in TypeScript 6):

```json
"paths": {
  "@pages/*": ["./src/app/pages/*"],
  "@components/*": ["./src/app/components/*"],
  "@state/*": ["./src/app/state/*"],
  "@services/*": ["./src/app/services/*"],
  "@core/*": ["./src/app/core/*"],
  "@shared/*": ["./src/app/shared/*"],
  "@testing/*": ["./src/testing/*"]
}
```

A Prettier import-sorting plugin (`@ianvs/prettier-plugin-sort-imports` or similar) keeps the import order the skill prescribes: Angular → `@shared/models` → `@core` → `@services` → `@state` → `@shared` → `@components` → relative.

## Initial-chunk gate (optional)

The lint bans keep `core/**` clean, but nothing stops `app.ts` or `app.config.ts` from statically importing a page. A build-time gate catches it: run `ng build --stats-json`, walk the outputs whose entry point is `main.ts` or the polyfills and everything they reach by static import, and fail when any input path matches `src/app/(pages|components|state/[^/]+)/`. Keep a `pageRoots` list of every `loadComponent` / `loadChildren` target and fail when one is not a lazy entry point; a new or moved page means updating that list. Wire it as `npm run check:initial-chunk` in CI. The zero-script alternative is a strict `initial` budget in `angular.json`, which catches growth but not the cause.

## Schematic naming

Component files are the CLI's default form (suffix-free since Angular 20). For the other kinds, pin the schematic options in `angular.json` (`schematics` → `@schematics/angular:service`, `:guard`, `:interceptor`, `:resolver`, `:pipe`, `:directive`) so `ng generate` matches the suffix and separator convention; confirm the option names for the workspace's Angular version through the `angular-cli` MCP server rather than memory.
