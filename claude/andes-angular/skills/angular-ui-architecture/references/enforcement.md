# Layer enforcement

## The ban table

| Files | May not import |
| --- | --- |
| `**/*.model.ts` | its folder's bans below, plus `@angular/*`, `@ngrx/*`, and any app file that is not a `*.model.ts` — by alias or relative path |
| `shared/**` | `features`, and anything in `core` that is not a `*.model.ts` |
| `core/**` | `features` |
| `features/<f>/**` | `features/<other>` |

## ESLint wiring

- Copy `assets/eslint-layer-bans.js` beside `eslint.config.js` and spread its blocks after the angular-eslint and NgRx blocks: `module.exports = defineConfig([...yourBlocks, ...layerBans(__dirname)])`. Options: `srcDir` (default `src`), `banForms` (default `false`; set `true` once the app is on Signal Forms, so `FormsModule` / `ReactiveFormsModule` imports fail everywhere, specs included), `skill` (the name quoted in messages). In an ESM config, change the `require` / `module.exports` lines.
- One `no-restricted-imports` block per top-level folder and one per feature, spec files exempt (`ignores: ['**/*.spec.ts']`), each banned folder as its alias (`@features/*`) and as `**/app/features/*`. Per-feature blocks are generated by reading `src/app/features` and negating the feature's own path — the top level only, so a feature's sub-areas share one block and are not isolated from each other. A new feature folder gets its block on the next lint run.
- Each folder block skips `**/*.model.ts` and has a twin for its models that repeats the folder's bans and adds the model bans, so no file is matched by two blocks.
- Four traps:
  - Flat config replaces a rule's options when blocks overlap, so every block repeats the forms ban instead of relying on a global one.
  - An exception negates the directory itself (`!@features/<f>`, `!**/app/features/<f>`), because the matcher cannot re-include a child of an excluded directory.
  - For the same reason, "except models" cannot be a gitignore pattern. It is an ESLint `regex` pattern — `^(@core/|(.*/)?app/core/)(?!.*\.model$)` for `shared`, and one covering every alias and relative path for models — which needs ESLint 9.7 or later.
  - `no-restricted-imports` matches the import *string*, not the resolved path, so a relative import with no `app/` segment (`../../features/x`) is not caught — imports that cross a top-level folder must use the alias. If the project adds `eslint-plugin-import`, `import/no-relative-parent-imports` closes that gap and `import/no-cycle` keeps `core/` acyclic.
- NgRx's `signalsTypeChecked` rules are added by hand and scoped to `**/*.ts` (`ngrx-signal-store`); unscoped, its parser would replace the template parser on `.html`.

## Path aliases

One alias per top-level folder, in `tsconfig.json`; no `baseUrl` (deprecated in TypeScript 6):

```json
"paths": {
  "@core/*": ["./src/app/core/*"],
  "@features/*": ["./src/app/features/*"],
  "@shared/*": ["./src/app/shared/*"],
  "@testing/*": ["./src/testing/*"]
}
```

A Prettier import-sorting plugin (`@ianvs/prettier-plugin-sort-imports` or similar) keeps the import order the skill prescribes: Angular → `@core` → `@shared` → `@features` → relative.

## Initial-chunk gate (optional)

The lint bans keep `core/**` clean, but nothing stops `app.ts` or `app.config.ts` from statically importing a lazy feature. A build-time gate catches it: run `ng build --stats-json`, walk the outputs whose entry point is `main.ts` or the polyfills and everything they reach by static import, and fail when any input path is under `src/app/features/` other than the eager landing feature. Keep a `lazyRoots` list of every `loadComponent` / `loadChildren` target and fail when one is not a lazy entry point; a new or moved feature means updating that list. Wire it as `npm run check:initial-chunk` in CI. The zero-script alternative is a strict `initial` budget in `angular.json`, which catches growth but not the cause.

## File naming

Use the CLI's defaults and pin no naming option (`typeSeparator`, `type`, `addTypeToClassName`) in `angular.json`'s `schematics`: `ng generate` then produces the names the skill prescribes — no suffix on components, directives, and services, a dash suffix on guards, interceptors, resolvers, and pipes. A workspace that `ng update` carried over from before v20 may have the 2016 options pinned; leave them until the whole workspace moves, and confirm option names for the workspace's Angular version through the `angular-cli` MCP server rather than memory.
